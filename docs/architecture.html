Factory Inventory Management System

A full-stack demo application for tracking inventory, orders, demand forecasts, backlog, and spending across factory warehouses — built with a Vue 3 single-page frontend and a FastAPI backend serving in-memory mock data.

3 Request & Data Flow

How a user interaction becomes rendered data — the path a single filtered request travels end to end.

1

User adjusts a filter

The FilterBar updates shared reactive state in the useFilters composable (warehouse, category, status, time period).

2

View calls the API client

A view (e.g. Dashboard.vue) reads current filters and calls a method on api.js, which serializes non-'all' values into URLSearchParams.

3

HTTP request to FastAPI

Axios issues GET /api/…?warehouse=&category=&status=&month= to the backend on port 8001. CORS middleware permits the cross-origin call.

4

Backend filters in memory

The route handler runs apply_filters() and filter_by_month() over the in-memory lists. Quarters (Q1-2025…) expand to their member months via QUARTER_MAP.

5

Validate & aggregate

Results are validated against Pydantic response_model types. Summary endpoints compute derived metrics (inventory value, low-stock counts, fulfillment rates) before responding.

6

Render via computed properties

JSON returns to the view; raw data lands in refs while computed properties derive display values (charts, KPIs, tables) that update reactively.

4 The Filter System

A single shared set of four filters drives nearly every data view — passed as query params and applied server-side.

Four global filters
Time Period — month or quarter Warehouse Category Order Status

A value of all is treated as "no filter" and is dropped before the request is sent. Inventory has no time dimension, so it ignores the month filter.

Server-side application
  • warehouseexact match
  • categorycase-insensitive
  • statuscase-insensitive
  • monthsubstring on order_date
  • Q1–Q4 2025expanded to 3 months each
